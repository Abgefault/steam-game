# CLAUDE.md — Green Empire architecture & conventions

Guidance for working on this Godot 4.7 project. Read this before changing
gameplay systems.

## High-level design

Authoritative **simulation state** is separated from **presentation**.

- All mutable game state lives in one plain `Dictionary`: `Game.state`
  (autoload `scripts/core/game_state.gd`). This is what gets saved, loaded,
  and driven by tests and the background simulation — one source of truth.
- Domain logic lives in **static** helper classes under `scripts/sim/*.gd`
  (`EconomySim`, `InventorySim`, `ProductionSim`, `MachineSim`, `RetailSim`,
  `StaffSim`, `MarketSim`, `AutomationSim`, `ComplianceSim`, `CampaignSim`,
  `EventsSim`, `ResearchSim`, `ObjectivesSim`, `OrdersSim`). They take the
  state dict as their first argument and never hold references to nodes.
- The 3D world (`scripts/world/*.gd`) and UI (`scripts/ui/*.gd`) only
  *visualize* and *drive* that logic. The exact same functions run whether a
  store is on-screen (visible customers) or simulated in the background — see
  `RetailSim.decide_and_buy` and `ActiveStoreProxy`.

### Autoload services (`project.godot` → `[autoload]`)

| Autoload | File | Role |
|---|---|---|
| `EventBus` | `core/event_bus.gd` | Typed global signals; systems never hard-reference each other |
| `DataRegistry` | `core/data_registry.gd` | Loads & validates `data/*.json` at boot |
| `SettingsService` | `core/settings_service.gd` | Persists & applies settings (`user://settings.cfg`) |
| `Game` | `core/game_state.gd` | Owns `state`, day close, top-level sim API |
| `SimClock` | `core/sim_clock.gd` | Central clock, speeds, day rollover |
| `SaveService` | `core/save_service.gd` | Versioned atomic JSON saves |
| `AudioService` | `core/audio_service.gd` | Music/ambience/SFX playback |
| `SceneRouter` | `core/scene_router.gd` | Top-level scene switching |

Dependency direction: world/UI → sim helpers → `Game.state` + `DataRegistry`.
There are no circular service dependencies and no single god-script.

## Authoritative data locations

**All** tunable content and balance values are data-driven in `data/*.json`,
generated by `tools/generate_data.py` (re-run it to change content; do not
scatter constants in scripts):

- `products.json` (26), `strains.json`, `machines.json` (6 types × 5 tiers)
- `districts.json` (5), `customers.json` (8 archetypes)
- `events.json` (42), `research.json` (33), `objectives.json` (63, incl. a
  tutorial chain + 15+ challenges), `achievements.json` (27)
- `balance.json` — every economy tuning constant. Read via
  `DataRegistry.bal("key")`, which reports missing keys at startup.
- `names.json` — person name pools.

Data is validated on boot (`DataRegistry._validate`); in debug builds missing
or malformed content fails loudly with actionable messages.

Audio is 100% original, synthesized by `tools/generate_audio.py` into
`assets/audio/*.wav` (see THIRD_PARTY_LICENSES.md).

## Commands

```bash
# Tests & simulations (all run through the real boot so autoloads exist)
godot --headless -- --run-tests      # tests/run_tests.gd — 123 assertions
godot --headless -- --smoke-test     # boot → new game → sim → save/load
godot --headless -- --smoke-world    # loads the 3D facility + HUD + tablet
godot --headless -- --economy-sim    # tools/economy_sim.gd → docs report

# Build
godot --headless --export-release "Windows Desktop" dist/GreenEmpire/GreenEmpire.exe
godot --headless --export-release "Linux" dist/linux/GreenEmpire.x86_64

# Rendered screenshots (needs a display; CI uses xvfb + software GL)
GE_SHOT_DIR=/tmp/shots xvfb-run -s "-screen 0 1920x1080x24" \
  godot --rendering-method gl_compatibility --rendering-driver opengl3 \
  -- --smoke-world --screenshot
```

## Conventions

- **Typed GDScript** everywhere. When a value is genuinely dynamic, annotate
  `: Variant` explicitly (the project treats the untyped-inference warning as
  an error at import time).
- Sim helpers are `static func` on `class_name`-decorated classes and mutate
  the passed-in `state` dict; they emit `EventBus` signals for UI updates.
- Every gameplay action that could be manual or automated calls
  `Game.log_action(dept, automated)` so the automation score reflects **real
  work done**, never equipment owned.
- UI is built in code through `UIKit` (`scripts/ui/ui_kit.gd`) for one
  consistent theme. Use `UIKit.label(..., wrap:=true)` / `UIKit.paragraph()`
  for multi-line text; plain labels do not autowrap (so they never collapse to
  one-character columns in grids). Center popups with `UIKit.center_popup`.
- No `TODO`/`FIXME`/placeholder markers in committed code; no dead
  commented-out blocks.

## Save format

`SaveService` writes `user://saves/<slot>.json`:

```
{ "save_version": 1, "engine": "...", "meta": {company, day, cash, stage,
  stage_name, automation, playtime, timestamp, date}, "state": { …Game.state… } }
```

Writes are atomic (temp file + rename) with a one-generation `.bak` backup.
`meta` powers the save/load list without loading full state. Bump
`SaveService.SAVE_VERSION` and add a branch in `SaveService._migrate` when the
state shape changes.

## Extending content

- **New product**: add a `prod(...)` entry in `tools/generate_data.py`, re-run
  it. Reference an existing `strain` id. Machine-tier / stage gates are fields.
- **New event / research / objective / achievement**: add an entry in the same
  generator; conditions are declarative and evaluated in the corresponding sim
  helper (`EventsSim`, `ResearchSim`, `ObjectivesSim`).
- **New machine tier**: extend the `tiers` array in `machines.json`.
- After any content change, run `--run-tests` (validates counts and formulas)
  and `--economy-sim` (re-checks balance) before committing.

## Platform / achievements

`SteamFacade` (`scripts/sim/steam_facade.gd`) is a no-op abstraction so a Steam
SDK can be attached later without touching gameplay. The local build has no
Steam dependency and runs fully offline.
